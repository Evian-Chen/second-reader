# Feature Specification: 首頁書籍搜尋和過濾功能

**Feature Branch**: `001-book-search-filter`  
**Created**: 2026-02-07  
**Status**: Draft  
**Input**: User description: "我想要建立首頁的書籍搜尋和過濾功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 關鍵字搜尋書籍 (Priority: P1)

使用者可以在首頁的搜尋框中輸入關鍵字（書名、作者、ISBN），系統會顯示符合條件的書籍列表。

**Why this priority**: 這是書籍平台的核心功能，使用者需要能夠快速找到想要的書籍。沒有搜尋功能，使用者將難以在大量書籍中找到目標。

**Independent Test**: 可以透過在搜尋框輸入書名關鍵字，驗證系統是否正確顯示相關書籍，並且結果與輸入的關鍵字相關。

**Acceptance Scenarios**:

1. **Given** 使用者在首頁，**When** 在搜尋框輸入書名關鍵字（如「原子習慣」），**Then** 系統顯示包含該關鍵字的書籍列表
2. **Given** 使用者在首頁，**When** 在搜尋框輸入作者名稱（如「詹姆斯・克利爾」），**Then** 系統顯示該作者的所有書籍
3. **Given** 使用者在首頁，**When** 在搜尋框輸入 ISBN，**Then** 系統顯示對應的書籍（如果存在）
4. **Given** 使用者輸入的關鍵字沒有匹配結果，**When** 執行搜尋，**Then** 系統顯示「找不到相關書籍」的友善提示訊息
5. **Given** 使用者輸入空白或只有空格，**When** 執行搜尋，**Then** 系統顯示所有可用書籍（或提示使用者輸入有效關鍵字）

---

### User Story 2 - 書籍分類過濾 (Priority: P1)

使用者可以透過選擇書籍分類（如：文學小說、商業理財、心理勵志等）來過濾顯示的書籍列表。

**Why this priority**: 分類過濾是搜尋功能的重要補充，幫助使用者快速瀏覽特定類型的書籍，提升使用者體驗和書籍發現率。

**Independent Test**: 可以透過點擊分類標籤，驗證系統是否正確過濾並顯示該分類的書籍，且其他分類的書籍不會顯示。

**Acceptance Scenarios**:

1. **Given** 使用者在首頁，**When** 點擊「文學小說」分類標籤，**Then** 系統只顯示分類為「文學小說」的書籍
2. **Given** 使用者已選擇「商業理財」分類，**When** 點擊「全部」標籤，**Then** 系統顯示所有分類的書籍
3. **Given** 使用者已選擇某個分類，**When** 切換到另一個分類，**Then** 系統立即更新顯示新分類的書籍
4. **Given** 某個分類沒有任何書籍，**When** 使用者點擊該分類，**Then** 系統顯示「此分類暫無書籍」的提示訊息

---

### User Story 3 - 搜尋與過濾組合使用 (Priority: P2)

使用者可以同時使用關鍵字搜尋和分類過濾，系統會顯示同時符合兩個條件的書籍。

**Why this priority**: 組合搜尋和過濾功能可以讓使用者更精確地找到目標書籍，提升搜尋效率和使用者滿意度。

**Independent Test**: 可以透過先選擇分類，再輸入關鍵字，驗證系統是否正確顯示同時符合分類和關鍵字的書籍。

**Acceptance Scenarios**:

1. **Given** 使用者已選擇「商業理財」分類，**When** 在搜尋框輸入「習慣」，**Then** 系統顯示「商業理財」分類中書名或作者包含「習慣」的書籍
2. **Given** 使用者已輸入搜尋關鍵字「設計」，**When** 選擇「設計」分類，**Then** 系統顯示「設計」分類中符合關鍵字的書籍
3. **Given** 使用者同時設定搜尋和分類，**When** 清除搜尋關鍵字，**Then** 系統保留分類過濾，顯示該分類的所有書籍
4. **Given** 使用者同時設定搜尋和分類，**When** 點擊「全部」分類，**Then** 系統保留搜尋關鍵字，顯示所有分類中符合關鍵字的書籍

---

### Edge Cases

- 當搜尋結果數量為 0 時，系統如何處理？
- 當使用者輸入特殊字元（如：@、#、$）時，系統如何處理？
- 當使用者輸入非常長的關鍵字（超過 100 字元）時，系統如何處理？
- 當網路連線中斷時，搜尋功能如何處理錯誤？
- 當 API 回應時間過長（超過 5 秒）時，系統如何提供使用者回饋？
- 當使用者快速連續輸入多個關鍵字時，系統如何避免過度請求 API？
- 當分類標籤數量很多時，UI 如何呈現（是否需要折疊或滾動）？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須提供搜尋輸入框，允許使用者輸入書名、作者或 ISBN 關鍵字
- **FR-002**: 系統必須在使用者按下 Enter 鍵或點擊搜尋按鈕時執行搜尋
- **FR-003**: 系統必須發送搜尋請求，包含使用者輸入的關鍵字（書名、作者或 ISBN）
- **FR-004**: 系統必須根據 API 回應顯示書籍列表，每個書籍顯示書名、作者、價格、書況等基本資訊
- **FR-005**: 系統必須提供分類過濾功能，顯示所有可用的書籍分類（如：文學小說、商業理財、心理勵志、人文社科等）
- **FR-006**: 系統必須在使用者選擇分類時，過濾並顯示該分類的書籍
- **FR-007**: 系統必須支援搜尋和分類過濾的組合使用
- **FR-008**: 系統必須在搜尋或過濾執行時顯示載入狀態（loading indicator）
- **FR-009**: 系統必須在搜尋結果為空時顯示友善的提示訊息
- **FR-010**: 系統必須在搜尋請求失敗時顯示錯誤訊息，並提供重試選項
- **FR-011**: 系統必須在搜尋輸入框獲得焦點時提供視覺回饋
- **FR-012**: 系統必須支援清除搜尋條件（重置為顯示所有書籍）

### Key Entities *(include if feature involves data)*

- **Book**: 書籍實體，包含 userBookId、isbn、title、author、description、bookCategory 等屬性
- **BookSearchQuery**: 搜尋查詢物件，包含 title、author、sellerAccountId、sellerDisplayName、bookCategory 等可選參數
- **BookCategory**: 書籍分類枚舉，包含 Undefined、Mandarin、World、GenreFic、LightNovel、Manga、Bl、Gl、History、Poem、Art、Philisophy、Religion、Biography 等值

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者可以在 3 秒內完成一次搜尋操作（從輸入關鍵字到看到結果）
- **SC-002**: 搜尋結果的準確率達到 90% 以上（結果中包含使用者期望的書籍）
- **SC-003**: 95% 的使用者能夠在首次使用時成功完成搜尋操作
- **SC-004**: 分類過濾的響應時間在 2 秒內完成
- **SC-005**: 搜尋和過濾組合使用的成功率達到 95% 以上
- **SC-006**: 系統能夠處理至少 1000 筆書籍資料的搜尋和過濾操作而不影響效能
- **SC-007**: 錯誤處理覆蓋率達到 100%（網路錯誤、API 錯誤、空結果等情況都有適當處理）
